# Roger Egito's Game Dev Portfolio

[My Website](https://roger-egito.github.io)

Built with [Astro](https://astro.build). No UI framework, no CSS framework, no runtime
dependencies. Design based on the
[Freelancer bootstrap theme](http://startbootstrap.com/template-overviews/freelancer/).

## Running it locally

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # type-checks, then writes dist/
npm run preview    # serves the built site
npm run check      # type-checks only
```

## Where things live

| To change | Edit |
| --- | --- |
| Colors, type, spacing | `src/styles/tokens.css` |
| Name, slogan, social links, CV link | `src/config/site.ts` |
| A game's details | `src/content/games/<slug>.mdx` |
| Which tags exist, and their icons | `src/config/tags.ts` |
| About text | `src/components/AboutCopy.astro` |
| Shared CSS (reset, buttons, layout) | `src/styles/global.css` |

Everything else is styled inside the component it belongs to, in that file's `<style>`
block. Astro scopes those styles, so a rule in `Header.astro` can't affect the footer.

`dist/` is generated by the build and is never edited by hand.

### Adding a game

1. Add `<slug>.mdx` and `<slug>.webp` to `src/content/games/`.
2. Point `img:` at the image and give the game an `order` higher than the others to
   show it first.

That one file produces the grid card, the popup and the standalone page. The build fails
if the image path is wrong, so a broken image can't reach the live site.

Source images are WebP, about 1920px wide. Astro generates the smaller responsive
versions at build time.

### Tags

A game lists its tags as lowercase strings, in any order:

```yaml
tags: [game designer, unity, horror, ludomancer]
startDate: 2024
endDate: 2025                    # optional, either date can be left off
team: "4 people"                 # optional, free text
blurb: "One line for the card."  # optional, defaults to the description's first paragraph

# Optional. A row of figures on the game's card (switched off for now in
# src/components/PortfolioGrid.astro).
metrics:
  - label: Downloads
    value: 10K+
  - label: Rating
    value: "4.1 ★ (99 reviews)"
```

A game with a `game:` embed also gets a "Playable right here on the portfolio" strip on
its card. There is no field to set for it.

Every tag must be registered in `src/config/tags.ts`, or the build fails with the file,
the tag and the valid alternatives:

```
[InvalidContentEntryDataError] games → destrua data does not match collection schema.
  tags.0: unknown tag "game desiner". Add it to src/config/tags.ts, or use one of: …
```

This way a typo stops the build instead of shipping a tag that matches no filter.

Tags are written in lowercase because the same words appear in lowercase in the hero
credit ("game designer and game developer for Cursed Blight"). Displayed labels are
title cased automatically. For names that title casing gets wrong, a tag sets its own
`label`, like `qa` → "QA" or `yougo` → "YouGo Games".

#### The registry

`src/config/tags.ts` holds three things:

- **`categories`**: the kinds of tag that exist. Each one sets its label in a game's
  detail table and where it appears on a card, through two independent settings:
  - `icons: 'left' | 'right' | 'none'`: whether its tags show as icons beside the date,
    and on which side. Technologies sit on the right and clients on the left because of
    this setting, not because of the markup.
  - `chips: true | false`: whether its tags show in the row under the card's text.

  A category can use both, either or neither. Technologies use `icons: 'right'` and
  `chips: true`, so they appear as an icon by the date and as a chip below. With
  `chips: false` they would appear as icons only.

  Turning `chips` off only removes a tag from the card's chip row. It still appears in
  the game's detail table and still counts for filtering.
- **`categoryOrder`**: the order categories appear in, left to right on a card and top
  to bottom in the detail table. Tags are sorted alphabetically *within* a category.
- **`tags`**: the tags themselves. Each names its category, and can set a `label` and
  an `icon`.

A new category is added to `categories`, then its id goes into `categoryOrder` where it
should appear.

The current categories:

| Category | Icons | Chips | What it's for |
| --- | --- | --- | --- |
| `platform` | right | yes | Where it's published (`steam`, `itch`, `google play`), or `private` |
| `role` | none | no | My role on the project. It has its own line on the card |
| `genre` | none | yes | Horror, tactics, dungeon crawler |
| `technology` | right | yes | Unity, Pygame. Shown in both places |
| `client` | none | no | Spelled out beside the year |
| `generic` | none | yes | Anything else worth flagging |

`platform` and `technology` share the icon row beside the year, and `categoryOrder`
puts platforms first.

#### Icons

A tag's `icon` is either **any Font Awesome free icon name** (`'unity'`,
`'network-wired'`, `'dice'`) or a file in `src/assets/tags/` (`'ludomancer.svg'`).
Anything containing a dot is treated as a file name, since Font Awesome names never
have one.

Font Awesome names need no setup. Search
[fontawesome.com](https://fontawesome.com/search?o=r&m=free), filter to Free, and use
the name as shown. Both free sets are read at build time, so every free icon is
available and only the `<svg>` each tag uses reaches the browser.

A name that doesn't exist fails the build and suggests the closest matches:

```
Unknown icon "netwrok-wired". Font Awesome's free sets have no fa-netwrok-wired.
Did you mean: network-wired?
```

A file that isn't in `src/assets/tags/` is also a build error, not an empty box on the
page.

A tag with no icon still appears in the chip row as text, with nothing beside the date.
Font Awesome covers Unity, Python, JavaScript, Steam, itch.io and Google Play, but not
Godot, Unreal, RPG Maker, Inky or any studio logo, so those use a file.

Icons show their name on hover, with the same tooltip as the social buttons.

#### Where they show up

On a portfolio card, the tags sit below the blurb as filter buttons, **outside** the
link that opens the game, since a button inside a link is invalid HTML. In a game's
detail table, they become one row per category.

### Hover previews

A card can fade from its still image into a short clip while the mouse is over it. To
add one, put `<slug>.mp4` next to the game's file. Nothing goes in the front matter, and
deleting the file brings back the plain still.

Clips are MP4, never GIF: an MP4 is a fraction of a GIF's size and decodes on the GPU.
To convert a clip (requires ffmpeg):

```bash
npm run preview:make -- "C:/path/to/clip.mp4" cursed-blight
```

The second argument is the game's slug and decides where the file goes, so the source
file can have any name. An optional third argument sets the CRF (quality): lower looks
better and is larger, higher is smaller, and 26 is the default. About 30 suits long or
high-motion footage.

The clip plays on hover with a mouse, on focus with a keyboard, and on press and hold on
a phone. Releasing the hold doesn't open the game.

The clip only downloads when someone hovers, so it adds nothing to the page's load, and
it never plays for visitors whose system asks for reduced motion.

### How the popups work

Clicking a game opens a native `<dialog>` over the homepage and changes the URL to
`/games/<slug>/`. Back closes it. The same URL is also a real page, so shared links, new
tabs and search engines all get proper HTML. The About dialog works the same way, at
`/about/`.

`<dialog>` handles focus trapping, Esc and the backdrop itself, so
`src/scripts/modal.ts` only handles the history and loads the trailer when a game is
opened, so the YouTube player isn't fetched for every game on the homepage.

## Notes

- Fonts are downloaded at build time and served from this domain, so loading the page
  makes no request to Google.
- Icons are inline SVG (`src/components/Icon.astro`), not an icon font.
- Visits are counted by a small collector of my own on Cloudflare Workers (`collector/`),
  with no cookies and nothing personal stored.

## Deployment

Pushing to `main` runs `.github/workflows/deploy.yml`, which builds the site and
publishes it to GitHub Pages. This requires **Settings → Pages → Source = "GitHub
Actions"**.
