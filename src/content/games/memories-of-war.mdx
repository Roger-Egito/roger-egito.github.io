### The project

Memories of War is a squad-based grid tactics game made with YouGo Games by a team of six. YouGo designed its core: a shared action economy, chess-inspired movement and positioning that matters. A previous programmer had already started the code when I joined.

### My role

I was a game designer and the sole programmer. My job was to design the game's levels and combat numbers, and take over its development.

### What I did

<TwoColumn image={movement} alt="A unit's movement range highlighted in green on the grid, with a Movement tooltip and the skill bar below" caption="Choosing where a unit moves">

**Development.** The code I inherited was tightly coupled, threw frequent exceptions, and made little use of polymorphism. Some data came from ScriptableObjects and the rest didn't. I refactored the entire codebase, then developed the rest of the game in Unity myself.

I reworked the classes so allies and enemies work the same way, built a better turn system, and rebuilt the whole attack and movement preview. I tried to reuse the existing attack and movement patterns, but ended up rewriting those too. Data is now a mix of ScriptableObjects and JSON, and the JSON doubles as the save data.

</TwoColumn>

<TwoColumn image={battlefield} alt="Battlefield of dirt paths and bushes with the player's squad in the middle and enemies closing in from both sides" caption="A battlefield mid-fight" side="right">

**Levels that build on each other.** I designed the levels and the obstacles that shape them, each one building on the last. The first level is a single enemy and teaches the basics. The second splits the map in two, adds more enemies, and shows how walls two tiles thick get in the way of both moving and attacking. The third arranges the walls so that movement itself gets hard. Each level asks you to use what the one before it taught.

</TwoColumn>

<TwoColumn image={statsTutorial} alt="Tutorial overlay explaining the turn panel, stats and map, skills, help and end turn, including the rule Attack minus Defense equals Damage" caption="The tutorial explaining turns, stats and skills">

**Balance.** I set the stats for every ally and enemy. They live in JSON, and I tuned them by playtesting the game a lot, making sure each character has its own specialty. Since I designed both the levels and the stats, playtesting let me balance them together. When a character was too strong or a level too hard, I could adjust either side.

</TwoColumn>

<TwoColumn image={heroStats} alt="A hooded mage character with a stats panel showing 5 health, 2 attack and 0 defense" caption="A hero's stats: 5 health, 2 attack, 0 defense" side="right">

**Small numbers.** Stats used to run to values like 25 and 105, which felt bloated to me. I reworked them into small, simple numbers, so the player can do the math in their head and work out a fight at a glance, the way Hearthstone and Magic: The Gathering do.

</TwoColumn>

### Outcome

It's playable in the browser and on Windows on itch.io.

It changed how I think about code. I now pay more attention to how a codebase is structured as a whole. When a game needs many characters, I want the pieces that make up a character to be modular, so adding one means putting existing parts together.
